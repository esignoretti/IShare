Key design notes:
- **S3 lifecycle minimum granularity is days**, not hours. Pre-signed URL X-Amz-Expires already enforces the 1-hour access window. Lifecycle rules are for storage cleanup after the pre-signed URL has expired.
- Mapping from ShareDuration prefixes to lifecycle days:
  - `shares/1h/` → 1 day (minimum S3 supports)
  - `shares/1d/` → 1 day
  - `shares/7d/` → 7 days
  - `shares/1m/` → 30 days
  - `shares/forever/` → no rule (never auto-delete)
- PUT bucket lifecycle: XML body `PUT /{bucket}?lifecycle HTTP/1.1`
- Operation is idempotent — always PUT the full configuration

    Add to S3Service:

    1. **New S3Error case**: `case lifecycleConfigurationFailed(String)` with description `"Lifecycle configuration failed: \(msg)"`

    2. **`configureLifecycleRules()`** — Public method, no parameters, async -> Result<Void, S3Error>. Builds lifecycle XML for all duration prefixes and calls `putBucketLifecycleConfiguration`. Returns success/failure.

    3. **`putBucketLifecycleConfiguration(xml: String)`** — Private method. Performs PUT `/{bucket}?lifecycle` with the XML body. Sends Content-Type `application/xml`. Returns Result<Void, S3Error>. On 200 response → success. On non-200 → `.lifecycleConfigurationFailed("HTTP \(code)")`.

    4. **Lifecycle XML builder** — Build XML matching the S3 API format:
    ```xml
    <LifecycleConfiguration xmlns="http://s3.amazonaws.com/doc/2006-03-01/">
        <Rule>
            <ID>expire-1h</ID>
            <Filter><Prefix>shares/1h/</Prefix></Filter>
            <Status>Enabled</Status>
            <Expiration><Days>1</Days></Expiration>
        </Rule>
        <Rule>
            <ID>expire-1d</ID>
            <Filter><Prefix>shares/1d/</Prefix></Filter>
            <Status>Enabled</Status>
            <Expiration><Days>1</Days></Expiration>
        </Rule>
        <Rule>
            <ID>expire-7d</ID>
            <Filter><Prefix>shares/7d/</Prefix></Filter>
            <Status>Enabled</Status>
            <Expiration><Days>7</Days></Expiration>
        </Rule>
        <Rule>
            <ID>expire-1m</ID>
            <Filter><Prefix>shares/1m/</Prefix></Filter>
            <Status>Enabled</Status>
            <Expiration><Days>30</Days></Expiration>
        </Rule>
    </LifecycleConfiguration>
    ```
    Build using string interpolation (matching existing `locationConstraintXML` pattern in `createBucket()`). Do NOT include a rule for `shares/forever/`.

    5. **Set auth headers** on the lifecycle PUT request matching existing patterns: `x-amz-access-key`, `Date`, `Content-Type`, `Content-Length`.
